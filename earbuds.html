藍牙耳機基礎

要把藍牙耳機的韌體搬到 Zephyr，得先懂耳機本身是怎麼運作的：聲音怎麼從手機跑到耳朵、為什麼會斷音、左右耳怎麼同步、晶片裡好幾顆核心怎麼分工。這頁從零講起，每個主題都有可以動手玩的動畫。

右下角可以暫停動畫、調整速度，點一下動畫也可以暫停。最後一節整理這些知識和 Zephyr 移植的關係。

耳機裡有什麼兩種藍牙與跳頻協定堆疊數位音訊壓縮緩衝與延遲時脈飄移真無線通話多核心資料路徑和移植的關係名詞

What's inside一副耳機裡有什麼

一顆耳機裡最重要的是一顆「藍牙音訊 SoC」，裡面通常不只一顆處理器：一顆 MCU 跑作業系統和藍牙協定、一顆或好幾顆 DSP 專門處理聲音、還有藍牙無線電和它自己的控制器。外面再接麥克風、喇叭、電池和感測器。點每個方塊看它負責什麼。

Classic vs. LE, frequency hopping兩種藍牙與跳頻

藍牙其實有兩套不同的技術，都用 2.4 GHz 頻段：

  • 經典藍牙（Classic，正式名稱 BR/EDR）：切成 79 個 1 MHz 的頻道，每秒換頻道 1600 次。傳統的藍牙耳機聽音樂（A2DP）、講電話（HFP）都靠它。
  • 低功耗藍牙（LE）：切成 40 個 2 MHz 的頻道，其中 3 個（37、38、39）專門用來廣播。原本用在手環、感測器，現在新一代的 LE Audio 也用它傳聲音。

為什麼要一直換頻道？2.4 GHz 很擠，Wi-Fi、微波爐、別人的藍牙都在用。一直跳來跳去，就算某個頻道被干擾，也只會掉一小段，重傳就好。更聰明的做法是適應性跳頻（AFH）：發現哪些頻道一直出錯，就把它們從跳頻清單拿掉。

進階：為什麼耳機晶片兩種都要支援

現在大部分手機播音樂還是用經典藍牙的 A2DP，所以耳機一定要支援 Classic。LE 則用在配對加速、App 控制（讀電量、設定 EQ）、找耳機，以及新的 LE Audio。同一顆晶片同時跑兩種，叫雙模（dual mode）。這也是為什麼耳機的藍牙協定堆疊比手環複雜很多：Zephyr 的 LE 很成熟，但 Classic 的音訊功能相對少，所以移植時通常保留原廠的 Classic 堆疊。

Protocol stack藍牙協定堆疊：一層一層往上疊

藍牙軟體分成很多層，每層只管自己的事，像寄包裹：最上面決定要寄什麼，中間負責打包、編號，最下面負責真的送出去。中間有一條很重要的分界線：

  • Controller（控制器）：無線電、跳頻、重傳、時序。時間要求非常嚴格（微秒等級），通常跑在藍牙子系統自己的核心或硬體上。
  • Host（主機）：L2CAP 以上的協定和各種 profile。跑在 MCU 上，就是會跟著 RTOS 一起搬家的部分。
  • 兩者之間用標準介面 HCI 溝通。所以理論上，換掉 host 不用動 controller。

Digital audio數位音訊：把聲音變成數字

聲音是空氣的壓力在連續變化。要用數位傳送，就要每隔固定時間量一次大小，記成一個數字，這叫取樣。兩個數字決定音質：

  • 取樣率：每秒量幾次。CD 是 44.1 kHz，耳機常用 48 kHz，電話只有 8 或 16 kHz。取樣率至少要是想保留的最高頻率的 2 倍，人耳聽得到約 20 kHz，所以音樂要 40 kHz 以上。
  • 位元深度：每個數字用幾個 bit 記。16 bit 有 65536 個等級，等級越多越細，雜訊越小。

這樣得到的原始數字串叫 PCM。下面為了看得清楚，故意用很少的取樣點和很少的等級：

位元深度

聲音最後要從 DAC（數位轉類比）出去推喇叭，麥克風的聲音要經過 ADC（類比轉數位）進來。晶片內部的 DSP 和這些轉換器之間，通常用 I2S 這種介面一個 sample 一個 sample 地傳，三條線：位元時脈（BCLK）、左右聲道切換（LRCLK）、資料（SDATA）。

Codecs壓縮：藍牙塞不下原始聲音

48 kHz、16 bit、立體聲的原始 PCM，一秒要 48000 × 16 × 2 = 1536 kbps。藍牙的空中速率雖然有 2～3 Mbps，但要扣掉跳頻、封包標頭、重傳，而且手機的 Wi-Fi 也在搶時間，實際能穩定給音樂用的只有幾百 kbps。所以一定要壓縮，負責壓縮和解壓縮的叫 codec（編解碼器）。

Jitter buffer & latency緩衝與延遲：為什麼會斷音

手機每隔固定時間送一包聲音，但無線傳輸不準時：遇到干擾要重傳，Wi-Fi 一忙整段都塞住。喇叭那邊卻必須一秒都不能停地播放，一旦沒資料可播，就會聽到「啪」一聲或斷音，這叫 underrun。

解法是在耳機裡放一個緩衝區（jitter buffer）：先存一段才開始播，封包晚到也有存貨可以撐。代價是延遲：緩衝越深，聲音比畫面慢越多，看影片、打遊戲會覺得對不上嘴型。這是耳機設計最基本的取捨。

每包是 20 ms 的聲音。干擾越大，重傳越多，偶爾還會有一整段 Wi-Fi 搶走時間。調大緩衝可以撐過更長的塞車，但延遲也跟著變長。實際產品常見的設定：聽音樂 150～250 ms，遊戲模式壓到 100 ms 以下。

Clock drift時脈飄移：兩邊的時鐘不一樣快

手機用自己的晶振決定「48 kHz」，耳機的 DAC 用耳機的晶振決定「48 kHz」。晶振都有誤差，單位是 ppm（百萬分之一）。差 50 ppm 聽起來很小，但 48000 × 50 ÷ 1,000,000 = 每秒差 2.4 個 sample。耳機播得比手機送得快一點點，緩衝區就會慢慢被吃光；慢一點點，就慢慢塞爆。不管哪種，最後都會斷音。

所以耳機一定要做速率補償：持續看緩衝區的水位，水位往下掉就讓播放稍微慢一點，往上漲就快一點。常見做法是非同步取樣率轉換（ASRC），或直接微調音訊時脈（PLL）。這通常是 DSP 和音訊驅動一起負責的。

True wireless stereo真無線：左右耳怎麼分工

傳統的經典藍牙 A2DP 是「一對一」的：手機只會連一個裝置、送一條立體聲串流。左右兩顆分開的真無線耳機（TWS），就要想辦法讓兩顆都拿到聲音，而且同時播出來（差超過幾十微秒，聲音的方向感就會跑掉）。常見三種做法：

  • 轉發：手機連主耳，主耳再轉送給副耳。簡單，但主耳要收又要送，電池消耗比較快，延遲也比較長。
  • 監聽：手機只連主耳，但副耳偷偷「聽」同一條連線，自己收資料；漏掉的再請主耳補。兩顆耗電接近。各家晶片廠都有自己的做法和名稱，是重要的競爭力。
  • LE Audio：標準本身就支援一支手機同時送兩條獨立串流（兩個 CIS），左右各一條，並用 presentation delay 約定同一個播放時間。前提是手機也要支援 LE Audio。

另外還有角色切換：主耳電量低或被收回充電盒時，要把主耳的身分和連線狀態無縫交給另一顆，手機那邊不能斷線。這些 TWS 功能都在原廠的藍牙協定堆疊裡，是移植時最不該亂動的部分。

Voice calls通話：比聽音樂更難

聽音樂是單向的，延遲 200 ms 也沒人發現。通話是雙向的，延遲太長兩個人會一直搶話，所以緩衝不能放太深；麥克風收進來的聲音還要先處理過才送出去：

  • 回音消除（AEC）：喇叭放出的對方聲音會被自己的麥克風收進去，要扣掉，不然對方會聽到自己的回音。
  • 降噪（ENC）：用好幾顆麥克風做波束成形，只保留嘴巴方向的聲音，壓掉旁邊的噪音。
  • 主動降噪（ANC）：另一回事，是讓「你」聽不到外面的噪音：用麥克風收外界聲音，產生反相的聲波抵消掉。時間要求極嚴，通常由專門的硬體或 DSP 處理。

這些全部在 DSP 上跑，MCU 上的 RTOS 主要負責建立通話連線（HFP 或 LE Audio）、切換模式、把資料在 DSP 和藍牙之間搬來搬去。

Multi-core data path多核心：一包聲音在晶片裡走過哪些地方

把前面的東西串起來：手機送出一包 A2DP 音樂封包，到從喇叭播出來，中間經過晶片裡好幾個處理器。按「下一步」一步一步看，每一步都標出是哪裡在處理，以及移植到 Zephyr 時會不會動到。

處理器之間交換資料，最常見的方法是共享記憶體 + 信箱中斷（mailbox）：資料放在雙方都讀得到的記憶體裡（通常是環形緩衝），寫好之後觸發一個中斷通知對方「有新資料了」。這就是 Zephyr 裡 IPC 驅動要做的事。

What this means for the port這些知識和 Zephyr 移植的關係

把耳機拆開來看，換 RTOS 主要影響的是 MCU 上的軟體。DSP 和藍牙控制器有自己的韌體，可以先不動，只要介面接得上。

主題在哪裡跑移植時要做什麼
跳頻、重傳、時序藍牙 controller不動。只要 HCI 介面接到 Zephyr（寫成 Zephyr 的 HCI 驅動）。
A2DP、HFP、AVRCP、TWSMCU 上的原廠 host保留原廠堆疊，透過 OSAL 跑在 Zephyr 上。這是風險最低的路。
App 控制、LE AudioMCU 上的 host之後可以評估改用 Zephyr 的 LE host。
codec、ANC、AEC、EQDSP不動。MCU 這邊的 IPC 驅動要寫成 Zephyr 驅動。
緩衝、速率補償MCU + DSP + 音訊驅動緩衝管理的執行緒優先權、中斷優先權要重新調，否則容易斷音。
I2S、DMA、DAC音訊驅動寫成 Zephyr 驅動，用 Devicetree 描述腳位和時脈。
省電整個系統接上 Zephyr 的系統計時器和電源管理，驗證待機和播放時的電流。

Glossary名詞小辭典

SoC
系統單晶片，把處理器、DSP、無線電、記憶體做在同一顆晶片裡。
DSP
數位訊號處理器，專門做大量數學運算，處理聲音最有效率。
BR/EDR
經典藍牙的正式名稱。BR 是基本速率，EDR 是增強速率（2、3 Mbps）。
LE
低功耗藍牙，40 個 2 MHz 頻道。
雙模
同時支援經典藍牙和低功耗藍牙。
跳頻、AFH
不停換頻道來躲干擾；AFH 會把一直出錯的頻道排除。
Host / Controller / HCI
藍牙軟體的上下兩半，以及兩者之間的標準介面。
Profile
某種用途的規範，例如 A2DP 聽音樂、HFP 講電話。
PCM
沒有壓縮的原始數位聲音，一串取樣值。
取樣率、位元深度
每秒量幾次、每次用幾個 bit 記。
Codec
編解碼器，負責壓縮和解壓縮聲音，例如 SBC、AAC、LC3。
kbps
每秒幾千個 bit，用來表示位元率。
Jitter
封包到達時間忽早忽晚的抖動。
Jitter buffer
先存一段聲音才開始播的緩衝區，用來吸收抖動。
Underrun
緩衝區空了、沒東西可播，會聽到斷音或爆音。
ppm
百萬分之一，用來表示晶振頻率的誤差。
ASRC
非同步取樣率轉換，把聲音微調快慢來補償時脈差異。
I2S
晶片之間傳數位聲音的介面，有位元時脈、左右聲道、資料三條線。
DAC / ADC
數位轉類比（推喇叭）／類比轉數位（收麥克風）。
TWS
真無線立體聲，左右耳完全分開、沒有線連著的耳機。
CIS / BIS
LE Audio 的連線式等時串流／廣播式等時串流（Auracast 用 BIS）。
Presentation delay
LE Audio 約定的播放時間點，讓左右耳同時出聲。
SCO / eSCO
經典藍牙的語音連線，佔固定時槽。
AEC / ENC / ANC
回音消除／通話降噪／主動降噪。
Mailbox
處理器之間互相發中斷通知的硬體，常和共享記憶體一起用。
