FreeRTOS → Zephyr 移植指南

寫給晶片廠的人：你們有一塊藍牙耳機開發板，原本跑 FreeRTOS，現在要搬到 Zephyr。藍牙驅動由藍牙部門負責，你要負責把晶片變成 Zephyr 平台、再把應用程式搬過去。這頁整理要學什麼、要注意什麼、出問題怎麼查、資料去哪裡找。

還不熟 Zephyr 的基本觀念（執行緒、Devicetree、Kconfig），建議先看 Zephyr RTOS 入門。這頁的勾選進度只存在你自己的瀏覽器裡。

API mappingFreeRTOS → Zephyr API 對照

大部分 API 都有對應，但有幾個「看起來一樣、其實不一樣」的地方，在「注意」那一欄。可以搜尋 FreeRTOS 或 Zephyr 的函式名稱。

FreeRTOSZephyr注意

建議先寫一層很薄的 OSAL（作業系統抽象層），讓應用程式碼先不用大改，之後再慢慢換成原生 Zephyr 寫法。Zephyr 沒有官方的 FreeRTOS 相容層（有 POSIX 和 CMSIS-RTOS v2，如果原本的程式已經是用 CMSIS-RTOS v2 寫的，可以直接用）。

osal.h（示意）
#include <zephyr/kernel.h>

/* 時間一律用毫秒，不要再用 tick */
static inline void osal_delay_ms(uint32_t ms) { k_msleep(ms); }

/* 號誌：在 ISR 和執行緒都可以呼叫同一個 give */
typedef struct k_sem osal_sem_t;
static inline int osal_sem_take(osal_sem_t *s, int32_t ms)
{
    return k_sem_take(s, ms < 0 ? K_FOREVER : K_MSEC(ms));
}

/* 優先權換算：FreeRTOS 數字越大越優先，Zephyr 數字越小越優先 */
#define OSAL_PRIO(frtos_prio)  ((OSAL_MAX_PRIORITIES - 1) - (frtos_prio))

Priority mapping優先權換算

這是移植時最常出錯的地方：FreeRTOS 的優先權數字越大越優先，Zephyr 剛好相反，數字越小越優先，負數還是「協作式」（不會被其他執行緒搶占）。下面填入你們現在的 task 優先權，看換算後的結果。

進階：要不要用協作式優先權？

Zephyr 的藍牙 host 有幾個內部執行緒預設用協作式優先權，確保協定處理不會被應用程式打斷。你的應用執行緒一般用搶占式（0 以上）就好。音訊這種很趕時間的工作，通常靠「中斷 + DMA + 高優先權執行緒」處理，而不是把一般執行緒改成協作式：協作式執行緒如果跑太久，會讓所有搶占式執行緒都等它。

Init levels開機初始化順序

FreeRTOS 專案通常在 main() 裡自己一個一個呼叫 xxx_init()，順序寫死在程式裡。Zephyr 的驅動是開機時自動初始化，順序由「等級」和「優先權數字」決定：

  • PRE_KERNEL_1：核心還沒啟動，只能做最基本的（時脈、中斷控制器、序列埠 console）。
  • PRE_KERNEL_2：還是沒有核心服務，但可以用 PRE_KERNEL_1 初始化好的東西。
  • POST_KERNEL：核心已經在跑，大部分驅動在這裡（I²C、SPI、I2S、codec 晶片）。
  • APPLICATION：應用程式層級的初始化。

    Pitfalls該注意的地方

    從 FreeRTOS 搬過來，最常踩到的坑。每張卡片都寫了症狀（你會看到什麼）、原因、怎麼查、怎麼改。可以依類別篩選。

    How to check出問題怎麼查

    Zephyr 很多東西是在建置時「算出來」的：Kconfig 會因為依賴沒滿足被悄悄關掉、Devicetree 會被好幾層檔案疊加。所以除錯的第一步，通常是去看建置後產生的最終結果，而不是你寫的原始檔。

    我想知道去看這裡
    Kconfig 最後到底開了什麼build/zephyr/.config。在 prj.conf 設了 =y 卻沒生效，建置訊息會有「assigned the value y but got the value n」的警告，通常是依賴的選項沒開。
    Devicetree 最後長什麼樣build/zephyr/zephyr.dts：板子、SoC、overlay 全部疊完的結果。
    Devicetree 巨集展開成什麼build/zephyr/include/generated/zephyr/devicetree_generated.h
    瀏覽、搜尋 Kconfig 選項west build -t menuconfig（文字介面）或 west build -t guiconfig（視窗介面），按 / 搜尋，還看得到每個選項的依賴。
    驅動初始化順序west build -t initlevels
    程式和 RAM 用在哪west build -t rom_report、west build -t ram_report；符號位置看 build/zephyr/zephyr.map。
    每個執行緒的狀態、堆疊用量開 CONFIG_SHELL=y 後打 kernel threads、kernel stacks；或開 CONFIG_THREAD_ANALYZER=y 定期印出。
    當機在哪一行fatal error 訊息會印出 PC 位址，用 arm-zephyr-eabi-addr2line -e build/zephyr/zephyr.elf 0x位址 換成檔名和行號（RISC-V 用 riscv64-zephyr-elf-addr2line）。
    逐行除錯west debug（燒錄並開 GDB）、west attach（不燒錄直接接上）。
    執行緒切換的時間軸CONFIG_TRACING=y 搭配 SEGGER SystemView 或 Percepio Tracealyzer。原本在 FreeRTOS 用過 Tracealyzer 的人會很熟悉。
    藍牙封包開 CONFIG_BT_DEBUG_MONITOR_UART=y（或 _RTT），把 HCI 封包送出來，在電腦上用 btmon 或 Wireshark 看。
    有沒有被不該呼叫的地方呼叫開發期間一律開 CONFIG_ASSERT=y：在 ISR 裡呼叫會等待的 API、參數錯誤，會直接停在出錯的那一行。
    核心在我們的晶片上正不正常west twister -p 你的板子 -T tests/kernel：跑官方的核心測試，SoC 移植完一定要跑。
    開發期間建議的 prj.conf 除錯選項
    CONFIG_ASSERT=y                 # 呼叫錯 API 馬上停
CONFIG_LOG=y
CONFIG_LOG_MODE_DEFERRED=y      # LOG 先排隊，由背景執行緒印，不卡住呼叫的人
CONFIG_SHELL=y                  # kernel threads / kernel stacks
CONFIG_THREAD_ANALYZER=y
CONFIG_THREAD_ANALYZER_AUTO=y
CONFIG_STACK_SENTINEL=y         # 堆疊溢位偵測（有 MPU 可改用 CONFIG_MPU_STACK_GUARD）
CONFIG_EXTRA_EXCEPTION_INFO=y   # 當機時印更多暫存器資訊
CONFIG_DEBUG_OPTIMIZATIONS=y    # 關掉最佳化，方便 GDB 逐行（量產要拿掉）

    Glossary名詞小辭典

    SoC 移植
    讓 Zephyr 認得一顆新晶片：記憶體配置、中斷、時脈、計時器、開機流程。
    HWMv2
    Zephyr 3.7 起的新版硬體模型，用 soc.yml、board.yml 描述 SoC 和板子。
    .dtsi / .dts
    Devicetree 檔。.dtsi 是 SoC 共用的部分，.dts 是一塊板子的完整描述。
    binding
    YAML 檔，規定某種硬體節點要寫哪些屬性，Devicetree 依照它檢查和產生巨集。
    compatible
    Devicetree 節點的「型號」字串，例如 "vendor,i2s"，用來配對驅動和 binding。
    pinctrl
    設定每隻腳位要當什麼功能（GPIO、UART、I2S…）的機制。
    HAL
    晶片廠提供的底層暫存器程式庫，Zephyr 驅動常建在它上面。
    module
    放在 Zephyr 主程式庫之外、由 west 一起下載的程式庫，例如 hal_nordic。
    west manifest
    west.yml，記錄要下載哪些 repo、哪個版本。晶片廠的 SDK 通常就是一份 manifest。
    blob
    不開源的二進位檔（例如控制器韌體），用 west blobs 下載。
    OSAL
    作業系統抽象層，把 RTOS API 包一層，換 RTOS 時應用程式碼不用大改。
    HCI
    藍牙 host 和 controller 之間的標準介面。
    IPC
    多核心之間傳資料的機制，Zephyr 有 ipc_service（常用 RPMsg）。
    init level
    驅動自動初始化的階段：PRE_KERNEL_1、PRE_KERNEL_2、POST_KERNEL、APPLICATION。
    LTS
    長期支援版本，會持續修 bug 和安全問題，適合產品鎖定。
    qualification
    Bluetooth SIG 的產品認證，換了藍牙協定堆疊就要重新做。
    twister
    Zephyr 的自動化測試工具，可以在模擬器或實體板子上跑大量測試。
    內容依 Zephyr Project 官方文件整理。Zephyr 每個版本的 API 和選項名稱可能會改，實際以你們鎖定版本的文件為準。
